- `Chunk` 只做证据，不进入主叙事中心

如果这套层级结构已经落地，GraphRAG 检索效果通常会比“纯向量 RAG”更稳定，体现在 3 点：

1. 召回更准  
先在报告层命中 `Finding/Topic/Event`，再下钻到证据层 `Claim/Chunk/Post`，能减少“只语义相似但业务不相关”的误召回。

2. 回答可解释  
每条结论都能沿桥接关系回溯到 `Claim -> Chunk -> Post`，回答时能给出处，不是黑盒生成。

3. 多跳问题更强  
像“某平台在某议题下的事件趋势及建议”这类问题，可通过图路径组合完成，不只靠单段文本相似度。

你可以用这个检索流程：

1. 查询理解：抽取 `平台/议题/时间/事件` 意图  
2. 报告层检索：先找 `Finding`（中心）  
3. 图扩展：取相邻 `Topic/Event/Recommendation/Metric`  
4. 证据回溯：沿 `DERIVED_FROM / SUPPORTED_BY_*` 找 `Claim/Chunk/Post`  
5. 混合重排：图相关性分 + 向量相似度分合并  
6. 生成答案：结论走报告层，证据引用走证据层

建议你做 3 个离线指标来判断“效果到底好不好”：

1. `Top-k 支撑率`：前 k 条结果里有多少能回溯到有效 `Post/Chunk`  
2. `路径完整率`：`Finding -> ... -> Claim/Chunk/Post` 是否闭环  
3. `答案引用率`：最终回答中有多少结论附带证据节点

一句话：  
这套两层图的价值不是“多了节点”，而是把“结论检索”和“证据检索”拆开，再通过桥接关系合起来，效果会更可控、可解释、可评估。



可以。你先构图，我这边给你一个可直接落地的 GraphRAG 检索设计（基于你现在的“证据层+报告层”）。

**目标**
- 检索入口以 `Finding` 为中心
- 结果必须可回溯到 `Claim/Chunk/Post`
- 支持“语义命中 + 图扩展 + 证据落地 + 重排”

**一、检索主流程（建议 v1）**
1. 查询解析  
抽取 `platform/topic/event/time`（先规则，必要时 LLM 补充）。
2. 报告层召回（主召回）  
先找 `Finding`（通过 `Section/Topic/Platform/Event` 约束）。
3. 图扩展（1~2 hop）  
从 `Finding` 扩到 `Recommendation/Metric/Event/Topic`。
4. 证据回溯（强制）  
沿 `DERIVED_FROM / SUPPORTED_BY_CHUNK / SUPPORTED_BY_POST` 找证据。
5. 混合重排  
`graph_score + semantic_score + evidence_score + freshness_score`。
6. 生成输入包  
输出“结论块 + 证据块 + 路径解释”。

**二、核心 Cypher（最小可用）**
1. Finding 主召回
```cypher
MATCH (f:Finding)-[:ABOUT_TOPIC]->(t:Topic)
OPTIONAL MATCH (f)-[:ABOUT_PLATFORM]->(p:Platform)
OPTIONAL MATCH (f)-[:SUPPORTED_BY_EVENT]->(e:Event)
WHERE ($topic IS NULL OR t.name CONTAINS $topic)
  AND ($platform IS NULL OR p.name CONTAINS $platform)
  AND ($event IS NULL OR e.name CONTAINS $event)
RETURN f.id AS fid, f.title AS title, f.statement AS stmt, t.name AS topic
LIMIT $k
```

2. Finding -> 证据链
```cypher
MATCH (f:Finding {id:$fid})
OPTIONAL MATCH (f)-[:DERIVED_FROM]->(c:Claim)
OPTIONAL MATCH (f)-[:SUPPORTED_BY_CHUNK]->(ch:Chunk)
OPTIONAL MATCH (f)-[:SUPPORTED_BY_POST]->(p:Post)
RETURN f, collect(DISTINCT c)[0..3] AS claims, collect(DISTINCT ch)[0..3] AS chunks, collect(DISTINCT p)[0..3] AS posts
```

3. Finding -> 建议
```cypher
MATCH (r:Recommendation)-[:RESPONDS_TO]->(f:Finding {id:$fid})
RETURN r.id, r.title, r.action
LIMIT 3
```

**三、重排公式（简单稳）**
- `final = 0.45*graph + 0.35*semantic + 0.15*evidence + 0.05*time`
- `graph`：topic/platform/event 匹配数 + 路径完整度
- `semantic`：query 与 `f.statement` 向量相似度
- `evidence`：是否有 `Claim`、是否有 `Chunk+Post` 双证据
- `time`：按 `Post.published_at` 衰减
